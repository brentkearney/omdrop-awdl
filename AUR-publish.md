## Publishing to the AUR

The AUR is a git-hosted recipe index — you push a PKGBUILD, not a binary. Users' helpers clone it and build locally.

 What's needed:

 1. An AUR account with an SSH public key registered, at aur.archlinux.org. Packages are pushed over SSH to:
    `ssh://aur@aur.archlinux.org/<pkgname>.git` the repo is created by your first push.
 
 2. `.SRCINFO` committed alongside PKGBUILD — generated by `makepkg --printsrcinfo > .SRCINFO`. The AUR web interface parses   only this file; a push whose .SRCINFO disagrees with the PKGBUILD is the single most common rejection.
 
 3. Sources fetched, not vendored. This is the real work for us. Our `PKGBUILD` builds from `${startdir}` — files sitting
    next to it. An AUR package must declare a `source=()` array pointing at a URL, with checksums. So it becomes

    `source=("$pkgname-$pkgver.tar.gz::https://github.com/brentkearney/omdrop-awdl/archive/v0.1.0.tar.gz")` 
    
    plus sha256sums, and package() reads from `$srcdir` instead. That's a mechanical but non-trivial rewrite, and it's the reason the v0.1.0 tag matters: the tarball URL is the tag.

 4. Naming. `brcmfmac-awdl-dkms` already follows the -dkms convention. Nothing to change.

 5. Dependency reachability. Every dependency must be installable from the official repositories, and now is: the sender's Python modules (`python-libarchive-c`, `python-pillow`, `python-zeroconf`, `python-ifaddr`) are in `extra`. The package no longer needs opendrop, which is only on the AUR.

 6. A clean-chroot build before pushing: extra-x86_64-build, or the aarch64 equivalent, to prove nothing depends on this machine's state. Given Asahi and DKMS, this is where surprises live.

 Two policy points to weigh: AUR packages are unsupported by Arch and reviewed only by other users — but they're public and
 permanent, and orphaned or broken packages get adopted or deleted by TUs. Also, the AUR is x86_64-centric; an aarch64-only kernel module package is unusual there, and Asahi users typically use the Asahi repos. Publishing to the Asahi community channels may reach your actual users better than the AUR does.

 ## AUR package submission

  When registration reopens, it's three commands — no review, no queue:

 ```
git clone ssh://aur@aur.archlinux.org/brcmfmac-awdl-dkms.git
cp ~/Projects/omdrop-awdl/aur/{PKGBUILD,.SRCINFO,brcmfmac-awdl-dkms.install} brcmfmac-awdl-dkms/
cd brcmfmac-awdl-dkms && git add -A && git commit -m "Initial import: brcmfmac-awdl-dkms 0.1.1" && git push
 ```

 Add your SSH key at My Account first; that's the only gate. Subscribe to aur-general
 (https://lists.archlinux.org/mailman3/lists/aur-general.lists.archlinux.org/) rather than checking the page — the notice says outright it won't tell you
 anything sooner.
